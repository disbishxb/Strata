# changes 目录元规则

## 0. 总则

> 时区约定：本目录及 `docs/` 下所有快照时间/日期均为北京时间（UTC+8）。
本目录不用于实时记录开发过程中的具体改动。它是发布前的汇总与整理区，
目的是在发布时据此撰写面向用户的正式更新公示。开发过程中不必逐条写入；
应在某部分工作完成后再归纳记录。

## 1. 适用范围
本目录用于记录 fork 相对原仓库（基线 Strata 1.0.0）的改动，供发布时总结。

## 2. 文件职责
- `01-user-facing-changes.md`：只放用户能看到的更新（功能、行为、界面、文案、权限提示、安装/打开方式变化等）。
- `02-developer-changes.md`：除“用户可见”外的所有改动（API、架构、依赖、构建、Manifest、数据格式、内部行为、性能、测试等）。
- `03-changelog.md`：按版本记录“本版相对上一版”的摘要；发布时从这里取。
- 本文件：规则。

## 3. 更新规则

> ps:AI不要一有改动就写,做完那部分的更新后再写,以免更新多了有用户更新却只写了开发者更新

- R1 任何改动先判断归属：用户可见 → `01`；否则 → `02`。
- R2 每次发布，把本版新增/修改条目汇总到 `03-changelog.md` 对应版本下，并注明来源文件。
- R3 `01` 与 `02` 只写“相对基线或上一版”的变化，不重复长期不变的内容；它们是归纳后的变化摘要，不是开发过程的实时日志。
- R4 条目要可追溯：能对应到文件/模块；必要时写路径。
- R5 用户可见条目要面向用户语言；开发者条目可用技术语言。
- R6 修改 `01`/`02`/`03` 后，同步更新本文件的“当前状态”一节。
- R7 源码改动的两种情况（详见 `docs/rule/ai-rule_rCN.md` §4.1）：
  - 情况 A（跨版本更新）：相对上一发布版本的变化，写入 `01` 或 `02`，并写明是跨版本更新。
  - 情况 B（单次未发布变更）：同一版本内发现并修掉的 bug、未发布中间改动不单独记录；只改“修好后仍不恰当”的内容，或合并叙述更合理的内容。
